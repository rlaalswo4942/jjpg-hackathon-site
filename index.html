JJPG 전주대 생활권 혼잡도 지도

다음 수업까지, 어디가 가장 낫습니까

전주대학교 생활권의 혼잡도를 블록 단위로 보여주고, 시간표를 등록하면 다음 수업 전 들를 만한 곳을 이동시간·대기·혼잡도까지 계산해 추천합니다. JJPG는 장소를 단순히 찾아주는 서비스가 아니라, 지금 다녀와도 되는지를 판단해주는 서비스입니다.

루트 · React 19 · TypeScript · Leaflet · OSRM

React: 화면을 만드는 데 널리 쓰이는 자바스크립트 도구

TypeScript: 오류를 줄여주는 자바스크립트의 확장 언어

Leaflet: 지도를 화면에 표시해주는 도구

OSRM: 실제 도로·보행로를 따라 길찾기 경로를 계산해주는 서비스

Overview

01

문제

01

도착해야 혼잡을 알 수 있다

혼잡재이동

점심시간이나 짧은 공강 시간에는 식당과 카페에 직접 도착한 뒤에야 혼잡 여부를 알게 됩니다. 이용이 어렵다면 다시 다른 장소로 이동해야 하고, 그만큼 공강 시간이 줄어듭니다.

02

지금 갈 수 있는지 미리 알기 어렵다

이동시간불확실성

가까워 보이는 장소도 다음 수업 건물과 반대 방향에 있을 수 있습니다. 이동시간과 대기시간까지 더하면 다음 수업에 늦을 수 있지만, 기존 지도와 리뷰 정보만으로는 이를 미리 판단하기 어렵습니다.

03

필요한 정보가 여러 곳에 흩어져 있다

지도시간표혼잡도

장소 위치는 지도에서 확인하고, 영업 정보는 검색 서비스에서 확인하며, 다음 수업 시간과 강의실은 별도로 확인해야 합니다. 각 정보를 직접 비교해야 하므로 최종 판단에 시간이 걸립니다.

04

검색되는 장소와 이용 가능한 장소는 다르다

검색 결과실제 이용 가능성

검색되는 장소라고 해서 현재 이용하기 좋은 장소인 것은 아닙니다. 혼잡도, 이동 방향, 남은 시간, 예상 대기시간을 함께 확인해야 실제로 방문할 수 있는 장소인지 판단할 수 있습니다.

02

해결 방법

01

출발지부터 다음 수업까지 전체 시간을 계산한다

이동시간대기시간이용시간안전 여유시간

단순히 가장 가까운 장소를 추천하지 않습니다. 현재 출발지에서 장소까지 이동하는 시간, 예상 대기시간, 식사·이용시간, 다음 수업 건물까지 이동하는 시간을 함께 계산해 추천 순위를 정합니다. 시간이 부족한 장소도 목록에서 삭제하지 않고, 이용 가능성이 낮은 순서로 배치해 사용자가 직접 선택할 수 있도록 합니다.

02

확인되지 않은 정보는 실제 정보처럼 보여주지 않는다

장소 데이터 검증

확인할 수 없는 장소와 임의로 입력된 데이터는 실제 정보처럼 노출하지 않습니다. OpenStreetMap, Nominatim, Overpass를 활용해 장소와 좌표를 확인하고, 건물 좌표는 campusBuildingFootprints.json이라는 하나의 기준 파일로 관리했습니다. 확인되지 않은 정보는 제외하거나 시연용 데이터임을 표시합니다.

OpenStreetMap: 전 세계 지도 정보를 누구나 만들고 수정하는 공개 지도 데이터베이스

Nominatim: 주소나 장소 이름을 좌표로 바꿔주는 검색 도구

Overpass: 지도 데이터베이스에서 원하는 정보만 뽑아오는 조회 도구

campusBuildingFootprints.json: 캠퍼스 건물들의 위치와 모양을 모아둔 데이터 파일

03

시간표와 생활권 지도를 연결한다

다음 수업강의실이동경로

사용자의 시간표에서 다음 수업과 강의실을 확인하고, 현재 위치와 장소의 위치를 함께 비교합니다. "어디에 있는가"가 아니라 "다음 수업 전까지 실제로 다녀올 수 있는가"를 기준으로 장소를 추천합니다.

04

사용자가 최종적으로 판단할 수 있도록 돕는다

추천주의 필요시간 초과 예상

추천 결과는 인공지능이 임의로 결정하는 방식이 아니라, 정해진 계산 규칙을 기반으로 산출됩니다. 각 장소의 거리, 혼잡도, 예상 대기시간, 다음 수업까지 남은 시간을 조합해 순위를 정하고, 사용자가 최종 결정을 내릴 수 있도록 판단 근거를 함께 제공합니다.

03

핵심 기능

01구현됨

혼잡도 지도

Leaflet6개 생활권 구역

전주대학교 캠퍼스와 주변 생활권을 6개 구역으로 나누어 혼잡도를 지도와 목록 형태로 표시합니다. 혼잡도는 여유, 보통, 혼잡 단계로 구분해 주변 상황을 빠르게 파악할 수 있도록 구성했습니다. 현재 혼잡도는 실시간 통신사·센서 데이터가 아닌 시연용 데이터입니다.

02구현됨

시간표 입력 및 다음 수업 추천

Tesseract.js이미지 문자 인식

시간표를 직접 입력하거나 시간표 이미지를 업로드해 자동으로 인식할 수 있습니다. 인식된 시간표를 바탕으로 다음 수업까지 갈 수 있는 곳을 추천합니다. 시간표는 연도와 학기별로 관리할 수 있도록 구성했습니다.

Tesseract.js: 사진 속 글자를 읽어서 텍스트로 바꿔주는 문자 인식 도구

03구현됨

실제 보행 경로 안내

OSRM경로 안내

출발지와 목적지를 선택하면 실제 보행자 경로를 계산해 지도에 표시합니다. 장소까지 이동하는 경로뿐만 아니라, 장소에서 다음 수업 건물까지 이동하는 경로도 함께 고려할 수 있습니다.

04구현됨

자유로운 출발지 선택

GPS출발지 설정

현재 위치, 지도에서 직접 선택한 위치, 검색한 장소, 캠퍼스 건물을 출발지로 지정할 수 있습니다. 위치 확인에 실패하거나 부정확한 경우에는 임의로 대체하지 않고 실패 원인을 안내해 다른 출발지를 선택할 수 있도록 했습니다.

GPS: 위성 신호로 현재 위치를 확인하는 기능

05구현됨

장소 검색 및 조건별 필터

음식 종류장소 유형생활 편의시설

식사, 카페, 편의점, 교내 시설 등 장소 유형별로 확인할 수 있습니다. 원하는 음식이나 메뉴를 검색하면 해당 메뉴를 제공하는 장소를 우선 표시합니다. 식사나 커피 등 이용 목적에 맞는 편의 기능이 없는 교내 건물은 관련 추천 목록에서 제외합니다.

06구현됨

추천 순위 및 정렬

가까운 순한산한 순혼잡한 순추천 순

장소를 가까운 순, 한산한 순, 혼잡한 순, 추천 순으로 정렬할 수 있습니다. 추천 순위는 거리뿐만 아니라 다음 수업까지 남은 시간, 이동시간, 예상 대기시간, 혼잡도와 이동 방향을 함께 고려해 결정됩니다. 시간이 부족한 장소도 완전히 삭제하지 않고 후순위에 배치합니다.

04

사용 기술

01

웹 화면과 상태 관리

React 19TypeScriptViteTailwind CSS v4Zustand

React와 TypeScript를 기반으로 화면과 기능을 구성했습니다. Vite로 개발 환경과 제작 과정을 관리하고, Tailwind CSS로 반응형 화면을 구현했습니다. Zustand를 활용해 지도, 시간표, 추천 결과와 같은 주요 상태를 관리합니다.

Vite: 개발 중인 화면을 빠르게 미리 보고 빌드해주는 도구

Tailwind CSS: 미리 만들어진 스타일 조각으로 화면 디자인을 빠르게 입힐 수 있는 도구

Zustand: 여러 화면이 함께 쓰는 정보(상태)를 관리해주는 도구

02

지도와 실제 이동경로

LeafletReact-LeafletLeaflet Routing MachineOSRM

Leaflet과 React-Leaflet으로 지도와 장소 정보를 표시합니다. Leaflet Routing Machine과 OSRM을 활용해 출발지와 목적지 사이의 보행 경로를 계산합니다. 추천 순위 계산과 실제 경로 안내 기능은 서로 분리해 관리했습니다.

React-Leaflet: React 화면 안에서 Leaflet 지도를 쉽게 쓸 수 있게 연결해주는 도구

Leaflet Routing Machine: 지도 위에 실제 이동 경로를 그려주는 도구

03

데이터 확인과 웹 서비스 배포

Tesseract.jsOpenStreetMapNominatimOverpassCloudflare PagesWrangler

Tesseract.js를 사용해 시간표 이미지에서 수업 정보를 인식합니다. 장소와 좌표 검증에는 OpenStreetMap, Nominatim, Overpass를 활용했습니다. 웹 서비스는 Cloudflare Pages에 배포하고 Wrangler로 관리합니다.

Cloudflare Pages: 만든 웹사이트를 인터넷에 무료로 올려 누구나 접속할 수 있게 해주는 서비스

Wrangler: Cloudflare Pages에 사이트를 올리고 관리할 때 쓰는 명령어 도구

04

인공지능 협업과 규칙 기반 추천

Claude CodeGitHub규칙 기반 추천

Claude Code는 구현과 반복 수정에 활용한 개발 협업 도구입니다. 문제 정의, 기능 범위 결정, 데이터 검증, 구현 결과 확인은 사람이 직접 수행했습니다. 추천 결과 역시 인공지능이 임의로 판단하는 구조가 아니라, 명시된 규칙과 데이터에 따라 계산됩니다.

Claude Code: 개발자의 지시에 따라 코드를 작성·수정하는 인공지능 코딩 도구

GitHub: 코드를 저장하고 여러 사람이 함께 관리할 수 있게 해주는 온라인 저장소 서비스

05

데이터 한계와 검증 원칙

01

현재는 시연용 데이터 중심이다

시연용 데이터

현재 혼잡도와 일부 대기시간·체류시간·이동시간은 실제 센서나 통신사 데이터가 아닌 시연용 또는 추정 데이터입니다. 따라서 실제 사용자 수, 정확도, 시간 절감 효과를 검증된 성과처럼 표현하지 않습니다.

02

데이터의 상태를 구분한다

데이터 상태 구분

데이터는 실제로 확인된 정보, 추정된 정보, 과거 조사 정보, 시연용 정보, 확인되지 않은 정보로 구분해 관리합니다. 확인되지 않은 장소와 좌표는 삭제하거나 보류하고, 필요한 경우 별도 상태로 표시합니다.

03

개발 과정에서 발견한 문제를 수정했다

개발 과정의 검증

개발 과정에서 GPS의 부정확 문제와 지도 기능 충돌 문제를 재현하고 수정했습니다. 또한 건물 좌표가 여러 파일에 분산되지 않도록 하나의 기준 파일로 통합하고, 추천 순위 계산과 실제 경로 안내 기능을 분리했습니다.

06

향후 확장 방향

01향후 확장

사용자 참여형 혼잡도 데이터

사용자 참여

사용자 제보, 방문 확인, 이용 후 평가를 통해 실제 혼잡도 데이터를 축적할 수 있습니다.

02향후 확장

매장 참여 기반 정보 제공

매장 참여

매장이 직접 혼잡도와 남은 좌석 정보를 제공하면 현재의 추정 데이터를 보완할 수 있습니다.

03향후 확장

센서와 무선 신호 연동

센서무선 신호

향후 대학 또는 매장과 협력할 경우 와이파이, 블루투스, 센서 데이터를 활용해 혼잡도 정확도를 높일 수 있습니다.

04향후 확장

예약 및 매장 관리 서비스 확장

예약매장 관리

남은 좌석 정보가 안정적으로 축적되면 장소 예약 기능, 매장용 관리 도구, 구독형 서비스로 확장할 수 있습니다.
